## 2. 주피터 노트북(.ipynb) 세팅 표준 규격 (16일차.ipynb 기준)
문제 생성 시 반드시 `python/16일차/16일차.ipynb`의 구조와 형식을 엄격히 준수합니다.

### A. 마크다운 셀 표준 템플릿
- 힌트, 의사코드(Pseudocode), 상세 작동 흐름, 풀이 팁 등은 사전에 일체 작성하지 않습니다.
- 지문 본문, 제약 조건, 입출력 예시 표(Table) 위주로 간결하고 명확하게 수록합니다.
- Markdown 형식:
```markdown
# N일차 Python 알고리즘 학습 (SQL의 경우: # N일차 SQL 데이터 분석 학습)

## 문제 1: [분류/유형] - [문제 제목] (Level N)

- **문제 출처**: [프로그래머스 [문제 제목]](URL)

---

### 문제 설명

[문제 지문 본문 설명]

- [제한 사항 1]
- [제한 사항 2]

---

### 입출력 예시 (SQL의 경우: ### 예시 테이블 및 기대 결과)

| param1 | param2 | return |
| --- | --- | --- |
| ... | ... | ... |
```
*(SQL의 경우 지문에 제공된 원본 테이블 구조/샘플 데이터 표와 `#### 기대하는 출력 결과 (RESULT)` 표를 마크다운 표 형태로 반드시 수록합니다.)*

### B. 코드 셀 표준 템플릿
- **상단 요약 주석**: 코드 셀 최상단에 문제 핵심 요구사항을 3~5줄 주석(`--` 또는 `#`) 형태로 명확히 수록합니다.
- **정답 및 로직 코드 작성 절대 금지**: 사전 정답 코드, 변수 선언, 로직은 일체 작성하지 않고 프로그래머스 웹사이트 기본 제공 수준의 스타터 코드만 제공합니다.
  - Python: `# [문제 설명]` 주석 + 기본 함수 껍데기(`def solution(...):` 및 `answer = 0\n    return answer`)
  - SQL: `-- [문제 설명]` 주석 + `SELECT ` 스타터 구문
- **사용자 코드 100% 보존**: 사용자가 이미 작성한 코드 셀은 피드백이나 추가 문제 세팅 시 절대로 수정하거나 초기화하지 않고 온전히 보존합니다. (교정 코드는 오직 답변 텍스트로만 제공)

### C. 당일 문제 누적 및 일차 관리 규칙
- **날짜 기반 1일 1파일**: `N일차`는 실제 날짜(자정 00:00 KST 기준)당 1개만 사용합니다.

- **일차 변경**: 실제 날짜(자정 00:00 KST)가 지났을 때만 다음 일차(`N+1일차`) 폴더 및 파일을 생성합니다.

  - 1-based 인덱싱과 0-based 인덱싱 차이 (`i`번째 -> `i-1` 인덱스) 유의.
- **Python 9일차 3번 (가장 큰 수)**:
  - 문자열 비교 시 자릿수가 다를 경우 단순 내림차순 정렬하면 오류 발생 (예: `'3'`과 `'30'`) -> 문자열 3회 반복(`x * 3`) 비교 정렬 패턴 활용.
  - `list.sort()`는 제자리 정렬로 `None`을 반환하므로 `"".join(list.sort())` 형태로 직접 사용 불가.
- **Python 10일차 1번 (큰 수 만들기)**:
  - `range(str_var)` 사용 시 `TypeError` 발생 -> `for num in number:` 문자열 direct 순회 활용.
  - `stack[0]`은 바닥 원소 -> 스택 상단 비교 시 `stack[-1]` 활용.
  - 다중 연속 제거 시 `if` 대신 `while stack and stack[-1] < num and k > 0:` 활용.
  - 내림차순 등으로 `k`가 남아있을 경우 `stack[:-k]` 슬라이싱 예외 처리.
- **Python 10일차 2번 (같은 숫자는 싫어)**:
  - `set()` 적용 시 연속 중복이 아닌 전체 중복 제거 및 순서 파괴 발생 -> `if not answer or answer[-1] != i` 단락 평가 `or` 조건문 활용.
- **Python 10일차 3번 (기능개발)**:

### SQL
- **SQL 7일차 1번 (오랜 기간 보호한 동물(2))**:
  - **`WHERE` 절 집계 함수 사용 불가**: `WHERE` 절에는 `MAX()` 같은 집계 함수를 쓸 수 없으며, 상위 N개 추출 시 `ORDER BY + LIMIT` 조합 활용할 것.
  - **함수명 및 오타**: MySQL 날짜 일수 차이는 `DATE_DIFF`가 아닌 **`DATEDIFF(종료일, 시작일)`** 사용.
  - **컬럼명 및 모호성**: 테이블의 이름 컬럼은 `ANIMAL_NAME`이 아니라 **`NAME`**이며, 다중 테이블 조인 시 `A.ANIMAL_ID` 처럼 테이블 별칭 필수 명시.
  - **정렬 방향**: "가장 길었던" 조건은 오름차순(`ASC`)이 아닌 **내림차순(`DESC`)** 적용.
- **SQL 7일차 2번 (식품분류별 가장 높은 가격의 식품 정보 조회하기)**:
  - **`GROUP BY` 기준 오설정**: `PRODUCT_ID`로 그룹화 시 개별 행이 출력됨 -> `CATEGORY`로 그룹화할 것.
  - **그룹화 시 타 컬럼 불일치**: `GROUP BY CATEGORY`를 한 뒤 `PRODUCT_NAME`을 그냥 뽑으면 최고가 상품명이 아닌 임의의 상품명이 반환됨 -> `WHERE (CATEGORY, PRICE) IN (서브쿼리)` 패턴 필수 적용.
  - **문자열 조건 오타**: `IN ("'과자', '국'...")` 처럼 전체를 따옴표로 묶으면 1개의 단어로 인식됨 -> `IN ('과자', '국', '김치', '식용유')` 개별 문자열 분리할 것.
- **SQL 7일차 3번 (취소되지 않은 진료 예약 조회하기)**:
  - **다중 테이블 조인 시 컬럼 모호성(Ambiguous)**: `PATIENT`, `APPOINTMENT`, `DOCTOR` 3개 테이블 조인 시 `PT_NO`, `MCDP_CD` 등 공통 컬럼은 `B.PT_NO`, `C.MCDP_CD` 처럼 테이블 별칭 필수 명시.
